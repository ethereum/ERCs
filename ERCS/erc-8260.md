## Abstract

ERC-8260 defines a sovereign, append-only dive logbook. Each record is a self-sufficient on-chain header (sequence id, UTC date, leave-surface time, maximum depth, total duration, bottom time, decompression table and schedule, end-of-dive and post-surface-interval repetitive groups, pre-dive surface interval, diving mode, unit system, primary breathing gas, and coarse location) plus a required `contentHash` (SHA-256 over the exact bytes of a UDDF 3.x dive profile) and an optional content-addressed `profileURI`. Attestations are optional [EIP-712](./eip-712.md) signatures that bind the dive id and the content hash; unattested dives remain valid self-reported records. Corrections use void/supersede, and compliant contracts are discoverable via [ERC-165](./eip-165.md). Multi-gas mixes, decompression stop lists, depth-time samples, and precise location stay in the off-chain profile, not in contract storage.

## Motivation

A diver's logbook is the evidence behind their experience: training agencies gate professional ratings on a minimum number of logged dives, regulations for diving at work require divers and employers to keep dive records, and those records are consulted when decompression illness or other incidents are investigated or claimed. Yet most logs are still paper or app entries the diver controls, attested by a signature, stamp, or initials that are easy to fabricate and hard for a third party to check. Dive computers already record depth, time, and gas data, and UDDF already gives that data a common export format, but nothing cryptographically binds a specific dive file to the buddy, instructor, device, or agency vouching for it.

This ERC supplies that binding without requiring a witness on every entry: unattested historic and recreational dives remain valid self-reported records, and consumers SHOULD treat attestation count and attester identity as the trust signal. Interoperability needs a shared header (with both commercial bottom time and scuba total duration), a shared content hash, and a shared optional attestation type, not an on-chain copy of every computer field.

### Why a dedicated ERC

A dive record is created by one party and verified by another, often in a different country and software stack: a dive computer from one manufacturer, a buddy or instructor using a logbook app from another, and an agency, employer, or insurer that must check the result. Without a common interface, every verifier must integrate every issuer, the problem that motivated [ERC-4626](./eip-4626.md), where the lack of a standard "forces each protocol to implement their own adapters which are error prone and waste development resources." [ERC-3643](./eip-3643.md) and [ERC-7943](./eip-7943.md) established that a real-world domain with regulatory and safety stakes warrants its own interface; this ERC follows ERC-7943's approach of defining only the essential surface and leaving implementation open. Generic data containers and attestation registries can record that someone signed something, but they do not define what a dive attestation commits to. As [ERC-8326](./eip-8326.md) observes for documents, without a shared commitment rule "two systems can hold the same canonical document representations but derive incompatible bundle commitments." This ERC therefore standardizes only what generic tools leave undefined: a minimal dive header, a canonical hash of the dive's existing UDDF export, typed-data attestations over that hash, and void and supersede semantics that preserve history. The full profile stays off-chain in the format dive computers and logbook software already exchange.

## Specification

The key words "MUST", "MUST NOT", "REQUIRED", "SHALL", "SHALL NOT", "SHOULD", "SHOULD NOT", "RECOMMENDED", "NOT RECOMMENDED", "MAY", and "OPTIONAL" in this document are to be interpreted as described in [RFC 2119](https://www.rfc-editor.org/rfc/rfc2119) and [RFC 8174](https://www.rfc-editor.org/rfc/rfc8174).

A dive logbook is a sovereign, append-only contract owned by one account (a diver, or an employer's log). Every ERC-8260 compliant contract MUST implement `IDiveLog` (below) and `IERC165`. Each record consists of:

1. A **self-sufficient on-chain header** that remains a meaningful logbook entry if the profile file is lost.
2. A required **`contentHash`**: SHA-256 of the exact octet stream of the UDDF 3.x file being committed (UTF-8, no BOM RECOMMENDED; no XML canonicalization; not a later re-export).
3. An optional **`profileURI`** locating that exact byte string; it SHOULD be content-addressed (`ipfs://` or `ar://`). The hash, not the URI, is authoritative.
4. Optional **attestations**: EIP-712 signatures that bind `diveId` and `contentHash`. Zero attestations is a valid self-report.

Everything else a commercial, military, or recreational record needs (stops, samples, environment, work performed, equipment, notes, names) lives in the hashed UDDF profile or off-chain.

### Data Types

```solidity
enum UnitSystem { Imperial, Metric }

enum DiveMode {
    OCRecreational,
    OCTechnical,
    CCR,
    SCR,
    Freedive,
    SurfaceSupplied,
    Saturation
}

struct DiveInput {
    uint32 diveDate;            // UTC calendar date as YYYYMMDD, e.g. 20260514
    uint64 startTime;           // Unix seconds UTC: leave surface
    uint32 maxDepth;            // tenths of FSW (Imperial) or MSW (Metric)
    uint32 durationSeconds;     // total time surface-to-surface, MUST be > 0
    uint32 bottomTimeSeconds;   // leave surface to beginning of ascent; 0 = not recorded
    DiveMode mode;
    UnitSystem units;
    uint16 o2Bps;               // O2 in basis points (2100 = 21.00%)
    uint16 heBps;               // He in basis points; N2 implied as 10000 - o2Bps - heBps
    bytes16 tableSchedule;      // ASCII family+schedule, right-NUL-padded; bytes16(0) = not recorded
    uint32 surfaceIntervalSeconds; // surface interval before this dive; 0 = not recorded / not applicable
    bytes1 repetitiveGroup;     // ASCII 'A'-'Z' at end of this dive; 0x00 = not recorded
    bytes1 repetitiveGroupAfterSI; // ASCII 'A'-'Z' after the SI preceding this dive; 0x00 = not recorded
    bytes4 coarseGeohash;       // geohash precision 4, or bytes4(0) if not recorded
    bytes32 contentHash;        // REQUIRED; SHA-256 of the exact attested UDDF bytes
    string profileURI;          // MAY be empty; SHOULD be content-addressed (ipfs:// or ar://)
}

struct DiveHeader {
    uint256 id;                 // contract-assigned sequence, starting at 1
    uint32 diveDate;
    uint64 startTime;
    uint32 maxDepth;
    uint32 durationSeconds;
    uint32 bottomTimeSeconds;
    DiveMode mode;
    UnitSystem units;
    uint16 o2Bps;
    uint16 heBps;
    bytes16 tableSchedule;
    uint32 surfaceIntervalSeconds;
    bytes1 repetitiveGroup;
    bytes1 repetitiveGroupAfterSI;
    bytes4 coarseGeohash;
    bytes32 contentHash;
    string profileURI;
}

struct VoidInfo {
    uint256 supersededById;     // 0 = voided without replacement
    bool isVoided;
    address voidedBy;
    uint64 voidedAt;
    string reason;
}

struct Attestation {
    address attester;
    uint64 attestedAt;
    uint256 nonce;
}
```

### Units

`UnitSystem` disambiguates the header's depth field only; UDDF file content follows UDDF's own units (metres, seconds).

| Field | Imperial | Metric |
|---|---|---|
| `maxDepth` | Tenths of feet of seawater (FSW) | Tenths of metres of seawater (MSW) |

### Field Encodings

| Field | Encoding |
|---|---|
| `id` | Assigned sequentially from 1; `1..getDiveCount()` is a complete scan. This is the dive number; original paper numbers, if any, live in the UDDF. |
| `diveDate` | `uint32` `YYYYMMDD`, a valid Gregorian calendar date with year >= 1970; not a Unix timestamp. The UTC calendar date of `startTime` MUST equal `diveDate`. |
| `startTime` | Unix seconds UTC, MUST be > 0: the instant the diver leaves the surface. Reach-surface is `startTime + durationSeconds`; leave-bottom is `startTime + bottomTimeSeconds` when bottom time is recorded. Reach-bottom is profile detail and lives in UDDF waypoints. |
| `maxDepth` | Tenths of FSW or MSW per `units`. MUST be > 0. |
| `durationSeconds` | Total dive time, surface to surface, in whole seconds. MUST be > 0. |
| `bottomTimeSeconds` | Time from leaving the surface in descent to beginning ascent, in whole seconds. `0` means not recorded (typical recreational computer logs that store only total time). If nonzero, MUST be <= `durationSeconds`. |
| `mode` | One of the closed `DiveMode` set; further apparatus detail lives in UDDF `<apparatus>`. |
| `units` | Selects the interpretation of `maxDepth`. |
| `o2Bps` / `heBps` | Basis points of the primary breathing gas. `0/0` means no cylinder (freedive). Air is `2100/0`; Nitrox 32 is `3200/0`; Trimix 18/45 is `1800/4500`. When gas is present, `o2Bps + heBps` MUST be <= 10000; residual nitrogen is `10000 - o2Bps - heBps` and is not stored. Multi-gas and deco mixes live in the UDDF. |
| `tableSchedule` | `bytes16` ASCII, right-NUL-padded (trailing `0x00`, never spaces); `bytes16(0)` = not recorded. Format `<TOKEN>` or `<TOKEN> <schedule>` with one space. Normative tokens map to UDDF `<divetable>` keywords: `USN` -> US-Navy, `PADI` -> PADI, `NAUI` -> NAUI, `BSAC` -> BSAC, `BUEHL` -> Buehlmann, `DCIEM` -> DCIEM, `CSMD` -> CSMD, `COMEX` -> COMEX, `OTHER` -> other. Printable ASCII `0x20`-`0x7E` only, plus trailing NULs; no interior NULs. Examples: `USN 60/40`, `USN 9/7`, `USN 60/40+10`, `PADI 60`, `DCIEM 15/50`. Recreational logs that do not use a table leave this zero. |
| `surfaceIntervalSeconds` | Surface interval before this dive, in seconds (UDDF `<surfaceintervalbeforedive>/<passedtime>`). `0` = not recorded or not applicable (first dive, or no reportable exposure in the window). Not derivable from other headers: the prior pressure exposure may be missing from this contract. |
| `repetitiveGroup` | `bytes1`; `0x00` = not recorded, otherwise ASCII uppercase `A`-`Z`. The designator at the end of this dive (upon surfacing, after decompression). Letters are table-family-specific: the table in `tableSchedule` defines the alphabet. If nonzero, `tableSchedule` MUST be nonzero. |
| `repetitiveGroupAfterSI` | `bytes1`; `0x00` = not recorded / first dive / surface interval >= 12 hours, otherwise `A`-`Z`. The new repetitive group after the surface interval that precedes this dive, i.e. the letter the diver held at leave-surface. If nonzero, `tableSchedule` MUST be nonzero and `surfaceIntervalSeconds` MUST be > 0. The letter after a still-running interval following this dive is not stored; it is looked up from `repetitiveGroup` and elapsed time when the next dive is logged. |
| `coarseGeohash` | `bytes4` holding the four ASCII characters of a geohash at precision 4, or `bytes4(0)` if not recorded. No precise coordinates on-chain. |
| `contentHash` | SHA-256 of the exact attested UDDF 3.x file bytes. MUST NOT be `bytes32(0)`. Do not hash a re-exported or pretty-printed copy; export tools may drop fields. |
| `profileURI` | RFC 3986 URI or empty. SHOULD be content-addressed (`ipfs://` or `ar://`). |

Publishers MUST mirror the header planning fields in the attested UDDF when they are nonzero: `<divetable>` uses the mapped keyword, `<surfaceintervalbeforedive>/<passedtime>` equals `surfaceIntervalSeconds`, and the letters and schedule are repeated in `<applicationdata>` and `<notes>`. The contract cannot check this. If header and UDDF differ, the record is inconsistent; consumers MUST NOT silently prefer one over the other. The header is the surviving summary when the file is unavailable: an availability rule, not an authority rule.

### Behavior Requirements

**Logging.** `logDive` and `batchLogDives` MUST revert `NotOwner` unless `msg.sender` is `owner()`. They MUST revert `InvalidDepth` if `maxDepth == 0`; `InvalidTimes` if `durationSeconds == 0` or if `bottomTimeSeconds != 0 && bottomTimeSeconds > durationSeconds`; `InvalidDate` if `diveDate` is not a valid `YYYYMMDD` (year >= 1970, month 1-12, day valid for the month) or does not match the UTC date of `startTime`; `InvalidContentHash` if `contentHash == bytes32(0)`; `InvalidGasMix` if gas is present and `o2Bps + heBps > 10000`; `InvalidTableSchedule` if `tableSchedule` is nonzero but is not right-NUL-padded printable ASCII whose first token is in the normative set; and `InvalidRepetitiveGroup` if either group letter is not `0x00` or `A`-`Z`, if a nonzero letter is logged with `tableSchedule == 0`, or if `repetitiveGroupAfterSI != 0` while `surfaceIntervalSeconds == 0`. Ids MUST be sequential from 1; headers MUST be append-only (never mutated or deleted); each dive MUST emit `DiveLogged`. Logging MUST NOT require an attestation. `bottomTimeSeconds == 0`, `tableSchedule == bytes16(0)`, both letters `0x00`, and `surfaceIntervalSeconds == 0` are valid and mean not recorded (for the surface interval: or not applicable, e.g. a first dive).

`batchLogDives` MUST validate each item identically to `logDive`, MUST revert the entire batch (no partial writes) if any item is invalid, MUST revert `InvalidBatchSize` if the length is 0 or exceeds `MAX_BATCH_SIZE` (100), and MUST emit one `DiveLogged` per dive.

**Historic and retroactive imports.** A dive MAY be logged long after it was made. Contracts MUST NOT reject a `startTime` in the past. No retroactivity flag is stored: consumers MAY compare the block timestamp of `DiveLogged` with `startTime` to detect retrospective entry.

**Trust.** Consumers SHOULD treat `attestationCount` and attester identity as the trust signal. Unattested dives MUST remain readable and are self-reported.

**Void and supersede.** `voidDive` MUST revert `NotOwner` unless called by `owner()`, MUST revert `DiveNotFound` for an unknown `diveId`, `DiveAlreadyVoided` if the dive was already voided, and `InvalidSupersede` if a non-zero `supersededById` equals `diveId`, does not exist, or is itself already voided. `supersededById == 0` voids without replacement. Voiding MUST NOT delete or mutate the header; it MUST emit `DiveVoided`. Consumers MUST check `isDiveVoided` before trusting a header or its attestations.

**Attestation.** See the EIP-712 typed data section. `attestDive` MUST revert `InvalidContentHash` if the `contentHash` argument is not the stored hash, `DiveAlreadyVoided` for a voided dive, `InvalidSignature` if recovery fails or the signature is non-canonical, `NonceMismatch` on a stale nonce, and `AlreadyAttested` when the recovered attester has already attested that dive. On success it MUST increment the attester's nonce and emit `DiveAttested` including `contentHash`. `cancelAttestationNonce` MUST be callable by `msg.sender`, increment that address's nonce by 1, and emit `AttestationNonceCancelled`.

**Reads.** An unknown `diveId` (0 or greater than `getDiveCount()`) MUST revert `DiveNotFound` from `getDive`, `isDiveVoided`, `getVoidInfo`, `attestationCount`, and `getAttestation`. An out-of-range attestation index MUST revert `InvalidAttestationIndex`. `attesterNonce` starts at 0. Indexers list a career from `DiveLogged` events or by iterating `getDive` over `1..getDiveCount()`; the standard intentionally provides no unbounded array getters.

**ERC-165.** `supportsInterface` MUST return true for the `IDiveLog` id (`0x4d89a8f9`) and for `0x01ffc9a7`, and false for `0xffffffff`.

### EIP-712 Typed Data

Attestations use the EIP-712 domain `name = "DiveLog"`, `version = "2"`, `chainId`, and `verifyingContract` (the dive log contract), preventing replay across contracts and chains.

```solidity
keccak256(
    "Attestation(uint256 diveId,bytes32 contentHash,address verifyingContract,uint256 nonce)"
)
```

The attester signs the EIP-712 typed hash of this structure, where `contentHash` is the stored SHA-256 digest carried as a `bytes32` field; signers MUST NOT keccak256 the UDDF file itself. The digest is `\x19\x01 ‖ domainSeparator ‖ structHash` per EIP-712. A wallet displaying the message shows `diveId`, `contentHash`, `verifyingContract`, and `nonce`.

`attestDive` recovers the attester from a 65-byte `r ‖ s ‖ v` signature with `v` in {27, 28}; it MUST reject signatures where `s > secp256k1n/2` (the [EIP-2](./eip-2.md) non-canonical form). Any address MAY submit the transaction; the recorded attester is the recovered signer. The `nonce` MUST equal the attester's current on-chain nonce (queryable via `attesterNonce`); it increments on every accepted attestation and on `cancelAttestationNonce`, which is how an attester invalidates signed-but-unsubmitted attestations.

Implementations SHOULD also accept [ERC-1271](./eip-1271.md) contract signatures through a non-normative overload or hook; this is not part of `IDiveLog`.

### UDDF mapping (non-normative)

The table maps header fields to their typical UDDF 3.x locations (paths under `profiledata/repetitiongroup/dive`). Hash the exact attested file bytes, not a reconstructed mapping and not a re-export that may have dropped fields.

| ERC-8260 | UDDF 3.x |
|---|---|
| `diveDate` / `startTime` | `informationbeforedive/datetime` (UTC); header `diveDate` is that instant's UTC `YYYYMMDD` |
| `durationSeconds` | `informationafterdive/diveduration` (seconds) |
| `bottomTimeSeconds` | Not a first-class UDDF element; derive from waypoints (leave surface to beginning of ascent) when known, otherwise 0 |
| `maxDepth` | `informationafterdive/greatestdepth` (metres in UDDF), converted to tenths of FSW or MSW per `units` |
| `o2Bps` / `heBps` | Primary `gasdefinitions/mix` fractions multiplied by 10000 (UDDF `<o2>` is a 0-1 fraction, e.g. `0.375`) |
| `coarseGeohash` | Derived at precision 4 from `divesite/site/geography` if the publisher chooses to publish a region; precise `latitude`/`longitude` stay in the UDDF or are omitted |
| `mode` | `informationbeforedive/apparatus` plus dive type (open-circuit, rebreather, surface-supplied, saturation, apnea) |
| `tableSchedule` | Family in `informationafterdive/divetable` (mapped keyword); full token+schedule string in `<applicationdata>` and `<notes>` as needed |
| `repetitiveGroup` | `<applicationdata>` and `<notes>`; do not use `<repetitiongroup>` for the letter; that element groups dives that belong together |
| `repetitiveGroupAfterSI` | `<applicationdata>` and `<notes>` |
| `surfaceIntervalSeconds` | `informationbeforedive/surfaceintervalbeforedive/passedtime` (seconds) |
| `contentHash` | SHA-256 of the entire attested file bytes, not of a single `<dive>` node and not of a later re-export |
| `profileURI` | Where that exact byte string is published (SHOULD be content-addressed) |
| Multi-gas, tanks, samples, deco stops, buddy, computer | `gasdefinitions`, `tankdata`, `samples/waypoint`, after-dive deco data, `buddy`, `equipment/divecomputer` |

## Rationale

### Prior Art

Generic data containers ([ERC-7208](./eip-7208.md)) and attestation registries such as EAS can record that a party signed a payload. They do not define what a dive attestation commits to, how the dive file is hashed, who may void or supersede a record, or how a verifier lists a career. [ERC-8326](./eip-8326.md) drew this line for document bundles: a generic container is not a document-specific commitment and lifecycle. [ERC-8328](./eip-8328.md) and [ERC-8329](./eip-8329.md) similarly treat generic attestations as insufficient where correction chains and a queryable, domain-specific log are required. This ERC takes that same approach for dive records.

### Header fields

- `id`: the durable dive number, assigned sequentially so `1..getDiveCount()` is a complete scan.
- `diveDate` (`YYYYMMDD`): lists a career by day without parsing a UDDF or depending on a single Unix-second key.
- `startTime`: the leave-surface instant; orders same-day dives; must match `diveDate`.
- `maxDepth`: the depth every logbook already shows.
- `durationSeconds`: total time surface-to-surface, what recreational logs and UDDF `<diveduration>` record.
- `bottomTimeSeconds`: commercial and US regulatory logs are built around bottom time (leave surface to beginning of ascent); `0` lets recreational logs omit it.
- `mode`: classifies the dive (open-circuit recreational or technical, rebreather, freedive, surface-supplied, or saturation) from the header alone.
- `units`: makes `maxDepth` unambiguous.
- `o2Bps` / `heBps`: a compact primary mix so the on-chain entry names the breathing gas; further mixes stay in the UDDF.
- `tableSchedule`: the table and schedule actually used, including modification, must survive loss of the UDDF. The short token keeps the field unambiguous and inside one storage slot; a family enum plus schedule string is longer and ossifies; the full keyword ("US-Navy 60/40+10") does not fit 16 bytes.
- `surfaceIntervalSeconds`: elapsed time since the last pressure exposure is required on commercial logs when under 24 hours; it cannot be derived unless the previous exposure is in this same book.
- `repetitiveGroup`: the end-of-dive letter materially changes residual nitrogen and next-dive planning (an F is not an A); it must be on the header. Its meaning is table-family-specific, hence the `tableSchedule` requirement.
- `repetitiveGroupAfterSI`: standard worksheets record the new group after the surface interval, not only the ending letter; this is the letter the diver held at leave-surface of this dive.
- `coarseGeohash`: a privacy-safe region (precision 4) so the entry has a place without publishing a pinpoint.
- `contentHash`: a required binding to the exact attested UDDF bytes, even when nobody has attested yet.
- `profileURI`: optional locator; the hash, not the URI, is authoritative.

### Functions

- `owner()`: discloses who may log, batch-log, and void.
- `logDive`: the single-dive write path, including unattested self-reports.
- `batchLogDives`: the historic-import path: one transaction for up to 100 thin headers at a measured ~155,000 gas each (reference suite, optimizer 200 runs, short content-addressed URI; ~15.5 million gas for a full batch), not the ~350,000 gas of a full on-chain form.
- `voidDive`: corrections to a safety record must remain auditable.
- `attestDive`: an optional witness signature over the dive's bytes, not a bare id; the argument hash must equal the stored hash.
- `cancelAttestationNonce`: lets an attester invalidate a signature they signed but never saw submitted.
- `getDive` / `getDiveCount`: sufficient to read a whole book without unbounded array getters.
- `isDiveVoided` / `getVoidInfo`: void is an overlay; consumers must be able to query it separately.
- `attestationCount` / `getAttestation`: bounded reads of an optional trust signal.
- `attesterNonce`: required for signers to build a valid typed message.

Dual units apply only to header depth; UDDF content follows UDDF's own units. The header planning fields (`tableSchedule`, both letters, `surfaceIntervalSeconds`) MUST be mirrored in the attested UDDF when nonzero; a mismatch is a defect, not a tie to break. Only the header and hash need to be in state: the packed header occupies three storage slots without a URI, and event logs, not extra storage, show when a dive was imported.

## Backwards Compatibility

This is a breaking rewrite of an unreleased Draft; no version of ERC-8260 has been merged. Early draft structs, the previous meaning of `diveDate` (Unix timestamp), and the previous attestation typehash are incompatible; the EIP-712 domain version `"2"` makes the change visible to signers. Contracts MUST still implement ERC-165.

## Reference Implementation

A reference implementation is provided at [SovereignDiveLog.sol](../assets/eip-8260/SovereignDiveLog.sol). It implements the complete `IDiveLog` interface with:

- Owner-gated `logDive`, `batchLogDives`, and `voidDive`; immutable owner set at construction.
- A packed three-slot header (without URI) with sequential append-only ids.
- EIP-712 attestation verification with `ecrecover`, 65-byte signatures, and low-`s` enforcement; SHA-256 is computed off-chain (the owner supplies the hash).
- `cancelAttestationNonce`, `MAX_BATCH_SIZE = 100`, and bounded read accessors only.

## Security Considerations

**Self-reported vs attested.** An unattested header is the owner's claim. An attestation proves only that a given address vouched for that exact `contentHash` at that time, not that the dive physically happened. Consumers SHOULD weigh attestation count and attester identity.

**Attester diligence.** An attestation vouches for the dive record as stored under that `diveId` on the `verifyingContract`: the stored header and the exact UDDF bytes its `contentHash` commits to. Attesters MUST review both before signing; a signature over a `contentHash` the attester never compared against the profile it claims to represent vouches for nothing. Clients requesting an attestation signature SHOULD surface the stored header fields next to the hash so this review is possible.

**Content binding.** Attestations that do not sign `contentHash` are not evidence of a witnessed profile. The contract rejects an attestation whose hash argument differs from stored state.

**Access control.** Only `owner()` can log, batch-log, or void; the owner SHOULD be immutable. Implementations SHOULD NOT use upgradeable proxies that can edit past headers; a lost owner key means a frozen book, and continuity is an application concern.

**Nonce cancellation.** `cancelAttestationNonce` is the revocation path for signed-but-unsubmitted attestations.

**Malleability.** Signatures with `s > secp256k1n/2` MUST be rejected, following [EIP-2](./eip-2.md).

**Void semantics.** Consumers MUST check `isDiveVoided` before trusting a header or its attestations. Void does not erase data.

**Privacy.** No names and no precise coordinates or site strings on-chain. `coarseGeohash` is optional and coarse; precise location, if recorded, stays in the UDDF. A wallet address plus a public dive history can still be identifying, and location data is personal data under privacy law; voiding does not make on-chain data disappear.

**Operational security.** Operators MAY omit `coarseGeohash` and `profileURI` and keep the UDDF private; `contentHash` still commits to it.

**False hashes.** The owner can commit to any 32 bytes; attestation is the honesty mechanism, and consumers can compare the hash against any published file.

**Gas.** The thin packed header keeps a dive near ~155,000 gas (measured with a short URI, optimizer 200 runs); deployment on an L2 is RECOMMENDED for cost-sensitive careers.

**ERC-1271.** Contract-signature support is a non-normative SHOULD; implementations that add it must still enforce every rule above.
